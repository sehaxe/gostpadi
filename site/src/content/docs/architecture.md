## Конвейер

```
код C → tree-sitter → IR → перенос строк → раскладка по модульной сетке → SVG
```

| Этап | Модуль | Ответственность |
|---|---|---|
| разбор | `frontend/cts.rs` | C-дерево → узлы. Не падает, не трогает текст |
| узлы | `ir.rs` | виды блоков и ветки |
| перенос | `layout/wrap.rs` | сколько символов влезет — вопрос геометрии |
| раскладка | `layout/` | координаты, линии, рельсы, нарезка на листы |
| лист | `sheet.rs` | геометрия А4, поля, вписывание |
| отрисовка | `generate/` | SVG |

Парсер отдаёт узлы **напрямую**. Раньше IR проходил через собственный
текстовый формат `.gvn` и обратно, и на этом терялись детали: приходилось
возвращать ключевое слово цикла в текст, чтобы парсер его снял, метки
кейсов носили служебный префикс, а пустые ветки склеивались. Удаление
формата убрало три костыля разом.

## Инварианты

Каждый проверяется тестом, а не комментарием:

| Инвариант | Чем проверяется |
|---|---|
| линии не заходят на блоки | `crossings_ok` |
| фигуры не перекрываются | `overlaps_ok` |
| в «конец» входит ровно одна стрелка | `single_entry_ok` |
| габарит накрывает всё, что рисуется | `assert_bounds_cover_labels` |
| перенос не теряет символы и не отрывает оператор | `layout::wrap::tests` |
| лист А4 и поля ЕСКД | `sheet.rs::tests` |
| зазоры кратны модульной сетке | `style.rs::tests` |

## Что было отвергнуто

Эти решения предлагались повторно, поэтому фиксирую причины.

### Plugin-мапперы вместо `match`

Предлагалось заменить `match node.kind()` на `Vec<Box<dyn NodeMapper>>`
с приоритетами, чтобы «новая конструкция = новый файл».

**Почему нет: диспетчеризация переезжает из compile-time в runtime.**
`match` проверяется компилятором на полноту — забытый `case` это ошибка
сборки. `Box<dyn NodeMapper>` это аллокация и разыменование на каждый узел,
и **забытый маппер не ловится ничем**: тихо уходит в fallback. Риск не
пропустить конструкцию не убирается, а становится невидимым.

Плюс к этому 10 конструкций C дают 10 файлов с четырьмя точками правки
каждый (impl, `pub use`, `Box::new`, регистрация) вместо одного `match`
на ~40 строк.

**Когда предложение станет верным:** если gostpadi станет библиотекой с
публичным API для чужих языков. До этого — инфраструктура без
пользователя.

### Sugiyama-лейаут вместо текущего

Предлагалось заменить раскладку на Sugiyama с constraint solver,
обоснование — «математические инварианты вместо правил».

**Почему нет: Sugiyama раскладывает DAG.** Здесь граф содержит циклы
(возврат в начало цикла), рельсы `break`, шину кейсов `switch`,
колонки `if` с зеркальной рельсой и специальные подписи. Ни один из этих
элементов не имеет выражения в алгоритме — их пришлось бы вводить как
частные случаи, то есть вернуть ту же кейс-логику внутри чужого каркаса.

Constraint solver на закладках — подпорки: задачи оптимизации требуют
solver'а, задачи «поставь блок на сетку» решаются арифметикой.

### Формат конфигурации TOML

Предлагалось вынести стили в `gostpadi.toml`.

**Почему нет:** ГОСТ — это не «можно настроить», а «так положено».
Позволяя менять толщину и заливку, утилита теряет право утверждать, что
выдаёт схему по ГОСТ. Стили и так выражены одной структурой с
производными от кегля метриками; TOML добавил бы зависимость `serde` +
`toml` и вопрос приоритета «файл против флагов командной строки».

### Модуль `.gvn` как входной формат

Предлагалось сохранить его как второй фронтенд. Он остался бы вторым
фронтендом со своим набором тестов, а выигрыш от его удаления (минус
один сериализационный круг) проще получить, просто убрав.

## Общий принцип

Симптом «в ядре растёт кейс-логика» почти всегда означает **потерю
данных на границе модулей**, а не сложность самого алгоритма.

Каждая из четырёх отвергнутых выше идей выглядела как лечение именно
этого симптома. Лечила же симптом точечная работа по границам: усечение
ушло из парсера в раскладку, терминаторы — из `.gvn` во фронтенд,
строгий C99 сменился fault-tolerant разбором.

Ищи потерю, а не переписывай алгоритм.
