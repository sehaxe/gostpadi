## Сборка

```bash
git clone https://github.com/sehaxe/gostpadi && cd gostpadi
cargo build --release
# бинарник: target/release/gostpadi
```

## Базовые примеры

```bash
gostpadi main.c -o main.svg            # код C -> main.svg
gostpadi 1/*.c 2/*.c -o out/           # пачка: каждой схеме свой .svg
gostpadi main.c --labels=ru            # надписи «начало/конец», «да/нет»
gostpadi main.c --trim -o main.svg     # лист по содержимому, в миллиметрах
gostpadi main.c --drawio -o main.xml   # редактируемая схема для draw.io
gostpadi main.c --check                # только проверка, без рисования
```

Результат — чистый векторный SVG: в Word, LaTeX и браузере без потерь.

## Опции

| Опция | Что делает |
|---|---|
| `-o ФАЙЛ/ПАПКА` | имя результата; для пачки — папка (или имя рядом с каждым входом) |
| `--labels=ru\|en` | язык надписей: «начало/конец» и «да/нет» или Start/End и yes/no (по умолчанию en) |
| `--font=N` | кегль текста в pt (по умолчанию 14), растит всю геометрию согласованно |
| `--lw=N` | толщина линий и усиков стрелок (по умолчанию 1.0) |
| `--trim` | без листа A4: схема ровно по содержимому, размер в миллиметрах |
| `--drawio` | файл draw.io (`.drawio`) с редактируемыми блоками |
| `--no-split` | не резать длинную схему на листы: один лист, общий масштаб пачки |
| `--landscape` | альбомный лист А4 297×210 вместо книжного 210×297; на пачку влияет один раз |
| `--check` | проверить схемы: пересечения, наложения, один вход в «конец» |
| `-h, --help` | справка |
| `-V, --version` | версия |

## В отчёт: `--trim`

Лист A4 удобен для печати, но в отчёт его не вставишь: схема занимает
часть страницы, а вокруг пустое поле. `--trim` отдаёт лист **ровно по
содержимому** — `width` и `height` заданы в миллиметрах, вписывания в лист
нет. В Word и LaTeX схема встаёт физического размера «миллиметр в
миллиметр», а блоки во всех файлах пачки совпадают.

```
$ gostpadi main.c --trim -o main.svg
<svg width="234.946mm" height="184.958mm" viewBox="-332.995 42.51 665.99 524.29">
```

## Править в draw.io: `--drawio`

`--drawio` отдаёт mxGraph XML, а не картинку: блоки — ромбы,
параллелограммы, капсулы и шестиугольники, рёбра — редактируемые линии
со стрелками в конце. Файл открывается в draw.io, diagrams.net и
Visio, и схема правится как схема.

## Функции файла

Рисуется **не только `main`**. Лабораторная работа — это десяток
функций, и старые версии молча теряли всё, кроме точки входа. Теперь на
выход идёт файл на функцию:

```
$ gostpadi util.c -o out/
out/util.svg        # main
out/util-fib.svg    # функция fib
out/util-sum.svg    # функция sum
```

Файл без `main`, но с функцией, тоже рисуется — раньше он давал пустой
лист и отказ, хотя рисовать было что.

## Пачка: что общего, а что нет

**Общее на всю пачку** — размеры фигур (`ГОСТ 19.701-90 п. 4.1.3`) и
ориентация листа. Страницы лабы обязаны совпадать.

**Своё у каждого файла** — масштаб листа. Иначе один широкий
диспетчер ужимал всю пачку: на реальной лабе из 18 файлов все листы
печатались на 30 % кегля, включая десятистрочные программы. Теперь
маленькая программа рисуется 1:1, а больная — на столько, на сколько
влезает.

Одинаковые имена получают префикс папки: `1/main.c` → `1-main.svg`.

## Длинный код: листы и соединители

Диспетчер на 12 кейсов в лист не влезает ни в каком масштабе. Раньше он
просто ужимался до нечитаемых 4 pt. Теперь ромб делится по ветвям, а
страницы склеиваются буквами в кружках — обычный приём разрыва схемы.

Цикл, тело которого не влезает, тоже режется: на первом листе верхняя
трапеция без нижней, на последнем нижняя без верхней. Цикл нигде не
выглядит замкнутым.

Имена листов сортируются по порядку: `main-01.svg`, `main-02.svg`. Без
ведущих нулей «main-10.svg» вставал выше «main-2.svg», а `main.svg` —
вообще после всех.

Если масштаб всё равно опустился ниже читаемого, утилита **скажет об
этом**, а не выдаст тихо нечитаемый лист. Обычно это глубокая
вложенность: порезка режет по верхнему уровню, а слишком высокое тело
цикла лежит на нём целиком.

## Коды возврата

| Код | Когда |
|---|---|
| 0 | схемы построены |
| 1 | не удалось прочитать или записать файл; `--check` нашёл нарушение инварианта; рисовать нечего |
| 2 | ошибка в командной строке |

Сбой **разбора** не бывает: битый код рисуется частично. Единственный
случай «схемы нет» — код, где нет ни одной функции с телом.
