## Требование и его природа

«Любой грязный C-код генерирует схему без падений» — это не
обязательство утилиты, а следствие выбранного разбора.

Разбор идёт через **tree-sitter**. Его грамматика разбирает любой текст:
непонятное место помечается `ERROR`-узлом, а дерево всё равно строится.
Фронтенд рисует такой узел обычным блоком с исходным текстом.

Строгий парсер C99 на том же коде завершался ошибкой и **не рисовал
ничего**. Для аудитории «студент с курсовой» это означало, что утилита
не работает почти никогда.

## Разбор потерь: что именно теряется

Схема на битом коде получается **частичной**. Правило простое:

> Напечатанное на схеме равно тому, что разбор понял. Непонятое напечатано
> сырым текстом.

Пример:

```c
int main(void) { if { printf("x"); } }
```

```
Start
if {
printf("x")
End
```

Условие не разобралось — оно напечатано как есть. Это честнее, чем
предположить, что имелось в виду, и нарисовать не то.

## Границы разбора

Два случая, где разбор теряет больше, чем обычно, обработаны отдельно.

**Функция не собралась целиком.** При `int main() { int a = ; return }`
прерванное объявление прячет от грамматики всю функцию, и `main`
не находится. Тело ищется по тексту — иначе был пустой лист с внятным,
но бесполезным «main не найден».

**`ERROR` прячет разобранное начало.** При `for (;;` незакрытая
скобка-цикл заворачивает в `ERROR` всё тело `main` вместе с тем, что
разобрать удалось. Фронтенд обходит детей `ERROR` прежде, чем рисовать
его текст целиком, — поэтому разобранное начало не теряется:

```c
int main(void) { x = 1; for (;;
```

```
Start
x = 1
End
```

## Чего не будет никогда

В API **нет ошибок разбора**. Фронтенд возвращает список узлов, а не
`Result`. Модуль ошибок удалён вместе с `.gvn`.

Проверка командной строки ищет не ошибки парсинга, а нарушения
геометрии: пересечения линий, наложения фигур, несколько стрелок в
«конец».

Единственный «пустой» результат — код без `main`. Тогда рисуется лист
с терминаторами и печатается предупреждение:

```
lab.c: в коде не найден int main(...) — схема пустая
```

## Проверка

В тестах фронтенда есть набор битого ввода, для которого требуется
ровно одно: терминаторы на месте и схема не пустая.

```bash
cargo test
```

Случайный вход не проверяется фаззингом в CI: tree-sitter не падает на
тексте по построению, а падать больше нечему — в пайплайне нет `unwrap`
на пользовательском вводе и нет паник в разборе.
