## Разбор C и C++

C-код читает `lang-c` (C11). C++ идёт через тот же фронтенд после
нормализатора `frontend/cpp.rs`: `using`, `std::`/`ns::`, ссылки,
`string`, `auto`, `constexpr`, brace-init и `static_cast` снимаются до
C-грамматики. Классы, методы, шаблоны/STL, range-for и default-аргументы
не поддержаны — на них движок честно отказывает.

Синтаксическая ошибка возвращает `ParseError` с файлом, строкой и
столбцом. Это не паника и не пустой лист:

```text
lab.cpp:4:1: в коде C: неожидаемый токен ... (using namespace std;)
```

`ParseErrorKind` отделяет виды отказа: `Syntax`, `Unsupported` и `Empty`.
В JSON (`wasm`, `serve`) вид приходит полем `kind`; CLI печатает
человеческое сообщение.

## Пустой вход

Если в файле нет ни одной функции с рисуемыми операторами, это
`Empty`, а не синтаксическая ошибка:

```text
lab.c: в коде нет рисуемых операторов — рисовать нечего
```

CLI завершается кодом 1. Файл без `main`, но с функцией, — не пустой
случай: рисуется тело этой функции. Функция, у которой `return` —
единственный оператор, пропускается: схема «Start → End» не несёт
информации.

## Все функции, а не только `main`

Лабораторная работа — это не одна функция `main`, а десяток функций.
Парсится каждая, у которой есть тело, и на выход идёт файл на
функцию: `util.c` → `util.svg` (main), `util-fib.svg`, `util-sum.svg`.
Прототипы из `#include` пропускаются: тела у них нет.

## Проверка

```bash
cargo test                                 # парсер, C++, раскладка, рендер, CLI
cargo test --test corpus_invariants        # весь корпус, включая .cpp
cargo test --test golden                   # эталон SVG для C++-схемы
```

`--check` проверяет не синтаксис, а геометрию: пересечения линий,
наложения фигур, несколько стрелок в «конец». Синтаксические ошибки
возвращаются до раскладки.
