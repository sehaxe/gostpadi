| Конструкция | Как рисуется |
|---|---|
| `printf` / `scanf` | параллелограмм ввода-вывода |
| `cin` / `cout` / `std::cin` / `std::cout` | параллелограмм ввода-вывода |
| `using namespace std;`, `std::` | не рисуются: это обвязка C++ |
| присваивания, `x = expr` | прямоугольник «процесс» |
| `if / else if / else` | ромб, ветки «да/нет», каскад — вертикальным стволом |
| `switch / case / default` | ромб, кейсы на шине; большой (5+) — сеткой в 2 колонки |
| `while` / `for` / `do-while` | шестиугольник «подготовка», тело возвращается в боковую вершину |
| `return` | скруглённый терминатор, конец ветки |
| `break` | обычный прямоугольник процесса, как в коде |
| `continue` | рельса к выходу нижней трапеции цикла (следующая итерация) |
| объявления переменных | с инициализатором — `a = 5`, без него выбрасываются |
| ссылки `int &a` | как объявление: в схеме остаётся `int &a` |
| `string` | объявление разбирается, в схеме остаётся `string s` |
| незнакомый синтаксис | ошибка с файлом, строкой и столбцом; без паники |

## Особые случаи

**`do-while`** рисуется тем же циклом, что и остальные: та же пара
трапеций, та же высота, тот же срез углов. Отличается только подпись —
в заголовке стоит `do while`, потому что в C условие проверяется
**после** тела, и без подписи шестиугольник врал бы.

**`break`** нарисован прямоугольником, а не рельсой. Решение сознательное:
рельса выхода визуально неотличима от обычного перехода и на схеме
читается как отдельная конструкция, которой в коде нет.

**`scanf_s`** (вариант MSVC с лишним аргументом размера буфера)
распознаётся как ввод-вывод, а все переменные в списке аргументов
сохраняются: `scanf_s("%lf%c", &radius, &chek, 1)` рисуется целиком.

**Пустая ветка `if`** существует всегда, даже при `if (x);`. Ромбу нужен
второй выход; иначе стрелка «да» уходила бы в никуда.

**`goto`** не поддерживается: метка рисуется обычным блоком, переход —
нет.

## C++

Файлы `.cpp`, `.cc`, `.cxx`, `.c++`, `.hpp`, `.hxx`, `.hh`, `.h++`
(и `.h`) идут через
тот же C-фронтенд: `using namespace std;` и `std::` снимаются,
`namespace X { ... }` разворачивается, `cin`/`cout` рисуются
вводом-выводом, ссылки, `string`, `constexpr`, `auto`, `ns::f()`,
`static_cast<T>(x)` и инициализация `int x{}` / `int x{5}` разбираются.
Классы, методы, шаблоны и STL-контейнеры (`vector`, `map`,
`std::function`), range-for и default-аргументы не поддерживаются —
это не компилятор C++.

## Перенос длинного текста

Текст ноды берётся из исходника **срезом по диапазону символов**,
а не печатается заново по дереву. Поэтому сохраняются дословно
пробелы, кавычки и содержимое строковых литералов.

Перенос строк — задача раскладки, а не парсера: текст делится по
модульной сетке, оператор не отрывается от операнда, а пробел после
оператора точкой переноса не служит (`a * b / 2` не рвётся на
`a *` / `b / 2`).
