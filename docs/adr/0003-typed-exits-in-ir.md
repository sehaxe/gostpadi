# Выходы потока типизированы в IR, сниффинг строк — только на границе

Исторически намерение «поток покинул блок» передавалось строкой
`Stmt::Text("break"/"continue"/"return …")`: layout декодировал её сам
(три копии `is_return`, строковые сравнения в column.rs, `is_io` в четырёх
местах) — на этом вырос баг с «двумя линиями» у ветки из одного break.
Решили: `Stmt` получил варианты `Break`, `Continue`, `Return(text)` и
`Tile { kind: Act|Io, text }`; раскладка и замер читают типы и текст не
парсят. Единственное место, где строки ещё распознаются — построение IR
во frontend'ах (`stmt_from_line` в gvn.rs, AST-варианты в c.rs).

## Consequences

- C-код по-прежнему идёт через текстовый проход `c_to_gvn` → `gvn::parse`
  (см. ADR-0001): сериализация типов обратно в текст тривиальна, а перенос
  длинных условий живёт в `gvn::parse` — прямой путь C→IR это заход
  «IR как seam» (перенести врап первым шагом).
- Компилятор проводит через все места строительства/потребления `Stmt`:
  новый вариант = ошибка компиляции в каждом потребителе, а не тихий
  неправильно нарисованный блок.
- `is_io` остаётся списком-данными (`IO_WORDS` в style.rs) с табличным
  тестом; слова-новинки (scanf_s и т.п.) добавляются в одном месте.
