# Фаза stdbool: три вшитые подстановки вместо препроцессора

lang-c разбирает уже обработанный препроцессором код, а gostpadi препроцессор
не запускает: `#include` выбрасывается, и тип `bool` из `<stdbool.h>`
становится синтаксической ошибкой — файлы студентов с `bool keep = true;`
не рисовались вовсе («4.c почему-то не рисует»). Встроили в подготовку
C-текста фазу подстановки ровно трёх объектных макросов stdbool:
`bool`→`_Bool`, `true`→`1`, `false`→`0`, по границам слов, не заглядывая
в строковые и символьные литералы, директивы пропуская.

## Considered Options

- Запускать настоящий препроцессор — отклонено: в Rust/WASM-экосистеме нет
  поддерживаемой библиотеки, а полный cpp раздул бы wasm-сборку сайта.
- Подменять только `bool` — отклонено: настоящий препроцессор раскрывает
  и `true`/`false`; контракт stdbool выполняется целиком, как это делали
  GCC/Clang и фейковая libc pycparser в питоновской версии gostpadi.
- Исполнять пользовательские `#define` — отклонено пока: к багу отношения
  не имеет, фазу можно расширить позже без смены интерфейса.

## Consequences

- Текст плиток из C-кода меняется: `keep = true` становится `keep = 1`,
  заголовок `while (true)` — `while 1`. Это отображение уже
  препроцессированного кода, как в учебнике.
- Граница фазы зафиксирована: функциональные макросы, `#if` и
  пользовательские `#define` не исполняются; ошибку это не маскирует.
